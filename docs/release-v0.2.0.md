# Little Code 0.2.0 preview

Little Code is a standalone desktop coding companion with a custom workspace, light/dark themes, Groq and local Ollama adapters, project intelligence and reviewed agent workflows. Version 0.2.0 adds format-aware file operations and stronger evidence requirements before the agent claims it has read or changed a file.

This is a public-safe summary of locally observed release evidence. It intentionally excludes private paths, credentials, user source, conversation storage, raw prompts and diagnostic logs. Original receipts remain local; counts below describe their recorded scopes rather than a complete PRD acceptance claim.

## File-aware workflows

- Text/code: read, create, edit and delete regular workspace files.
- Notebooks: read source cells and propose cell creation, insertion, replacement, patching or deletion. Unrelated content is preserved; changed code clears stale outputs and execution counts.
- DOCX/PPTX: extract bounded paragraph/slide text, create simple documents and propose text replacements through review.
- PDF: extract supported page text, create supported text PDFs and append pages. Existing-page reflow and scanned-PDF OCR are not supported.
- Mutations: native review before application and exact-byte checkpoint recovery. Directory deletion, symlink traversal, sensitive files and dirty editor conflicts are denied.

Legacy `.doc` and `.ppt` are not supported. Complex layouts, arbitrary embedded objects and every document encoding have not been established by this preview’s text fixtures. Document content is untrusted input and does not grant permissions.

## Reproduce and assess limits

```sh
npm ci
npm run check
node scripts/repository-audit.mjs
npm run website:check
npm run website:build
```

Native smoke scripts require a prepared Windows desktop build and isolated profiles. `scripts/smoke-file-tools.mjs` checks the review/recovery fixtures; `scripts/smoke-groq.mjs` checks native protocol/history fixture behavior. `scripts/probe-groq-live.mjs` is a separate deliberate authenticated check against owned fixtures and native SecretStorage. A source-only CI run does not establish native packaging or real-model inference.

Accepted native fixture changes and rejected live-provider proposals establish different scopes. Accepted mutations/checks generated by a live model, installed Ollama inference, arbitrary private repositories and complete PRD coverage remain separate acceptance work. The setup has not undergone installation/upgrade/uninstall smoke testing. Signing and full dependency-notice/license review remain public-release work; these checks do not imply those steps passed.

Original Little Code licensing has not been selected by the maintainer. Existing third-party and font notices retain their own terms; public visibility does not supply a license for original source. See [publishing guidance](github-publication.md) for release and Vercel deployment steps.
