# Tools and permissions

Every tool declares a JSON schema, risk, strict input validator, and execution function. The [permission engine](../src/little/permissions/permission-engine.ts) checks requested tools even if the model calls something it was not advertised. ASK/PLAN permit SAFE operations; EDIT adds WORKSPACE_WRITE proposal tools; AGENT adds EXECUTION. SENSITIVE and DANGEROUS actions remain denied.

## Repository reads

`read_notebook` is SAFE and reads bounded code/markdown cell source with original citations. Optional `startCell`/`endCell` selects up to 20 cells; `startLine`/`endLine` selects up to 120 source lines within one cell. Outputs, attachments and execution metadata are omitted. Input is limited to 8 MiB, and no cells execute. Generic notebook `read_file` uses source extraction; JSON line reads/search are excluded. `read_document` adds protected DOCX/PPTX/PDF text with paragraph/slide/page citations, complete input up to 16 MiB, bounded archive expansion and an isolated PDF worker. Generic `read_file` routes supported documents through the same parsers. `inspect_file` provides exact-byte metadata without claiming a content read. See [file workflows](file-tools.md) and [notebook context](repository-context.md).

[Read-only tools](../src/little/tools/read-only-tools.ts) cover workspace information, directories, bounded file/range reading, filename/text search, active file, selected code, and diagnostics. [WorkspaceService](../src/little/tools/workspace-service.ts) respects `.gitignore` and `.littleignore`, skips generated/vendor content, and bounds results. It checks normalized and real paths to reject traversal and linked escapes. Common secret paths are excluded independently of ignore rules; source redaction remains heuristic.

[Repository tools](../src/little/tools/repository-tools.ts) add SAFE `get_repository_map`, `find_relevant_files`, and `search_symbol`. Each query refreshes current inventory/policy before returning bounded lexical metadata, candidate reasons, or declaration-line hints. Observations are capped at 18,000 serialized characters and contain no raw cached source. They do not satisfy AGENT's source-inspection gate; follow up with a real source read. [Repository context](repository-context.md) describes indexing, file/link limits, source budgets, and provenance.

## Reviewed file changes

`propose_file_edits` stages unique literal text replacements, new UTF-8 files, or deletion of regular files. Text proposals are bounded to eight files, 32 replacements each, 256 KiB per file and 1 MiB combined original/proposed bytes. `propose_notebook_edits` changes valid notebook cells; `propose_document` creates supported documents, replaces DOCX/PPTX text or appends PDF text pages. Format proposals and binary deletion preserve exact original bytes, bounded to 16 MiB per file and 32 MiB aggregate checkpoint bytes. Dirty text editors and notebooks must be saved first. Sensitive, ignored, generated, symlink/junction, hard-link alias and ignore-policy paths remain excluded; directories cannot be deleted. Format writers use source summaries for native review, never binary payloads in model observations. See [supported operations and limits](file-tools.md).

[EditReviewHost](../src/extension/edit-review.ts) opens original/proposed text in native diff editors. The user must review before **Accept changes**; **Reject** leaves the proposal unapplied. Only the host can mint acceptance, and it checks workspace trust and dirty buffers. The service rechecks original fingerprints before and during installation. Native preview documents and acceptance grants are never returned in model observations or sent in webview messages.

Original bytes and version 2 mutation intents are synced to private extension `workspaceStorage` before workspace mutations. Checkpoint cards and **Little: Restore Checkpoint** support recovery, including interrupted apply/restore operations discovered after restart. Native restoration requires confirmation and rechecks trust, active project and dirty buffers. Later edits/deletions remain conflicts. Actual child-process crashes exercise write-ahead boundaries; Windows power-loss durability and external open-file/ancestor locking are not guaranteed. Checkpoints cover accepted file transactions, not command side effects. See [checkpoint recovery](checkpoints.md).

## Approved project commands

[run_command](../src/little/tools/command-tools.ts) accepts separate `program` and `args` tokens, a relative project `cwd`, a visible `purpose`, and `timeoutMs`. [ProjectCommandService](../src/little/tools/command-service.ts) supports selected check/local-script actions for npm, pnpm, yarn, bun, node, Python/pytest, cargo, go, dotnet, tsc, and git. Its strict schema bounds arguments to 32 tokens of 512 characters, purpose to 500 characters, and timeout to 1–120 seconds (default 60).

Direct shell/eval syntax, absolute/parent argument paths, URLs, package installation, credential operations, network commands, and destructive actions are rejected. The [risk classifier](../src/little/permissions/command-risk.ts) informs policy; classification alone never authorizes execution. On Windows, verified `.cmd`/`.bat` toolchain shims use a constrained native `cmd.exe` invocation; the model does not supply a shell script.

The host displays the exact request and waits for **Allow once** or **Reject**. Allow requires native confirmation and a trusted workspace before creating a private one-use grant bound to the immutable proposal. Grants cannot be forged by JSON, reused, or transferred to another request. Executable and working-directory identities are rechecked before launch. Only one command is active at a time.

Commands run as the current user without an OS sandbox. Approved project scripts can write outside their launch directory or access the network even when their outer command tokens satisfy policy. Native confirmation states these permissions and that file checkpoints do not cover command side effects. The child environment strips known credential variables and Electron/editor/Node preload controls.

Combined stdout/stderr capture is capped at 64 KiB; exceeding it stops the command. Results remove terminal control sequences, redact likely secrets, and return at most 16,000 characters with a truncation flag. Status is `exited`, `rejected`, `cancelled`, `timed_out`, `output_limit`, or `failed`, with observed exit code and duration. Stop, timeout, and output-limit handling terminate the owned process tree; failure to confirm tree shutdown is reported as failure. A five-second forced-stop deadline prevents an unconfirmed shutdown from waiting indefinitely.

The [runtime](agent-runtime.md) separately tracks latest command outcomes and bounds verification/repair attempts. An exited command is evidence about that command, not overall correctness. Native/process tests and fixtures do not establish a live Groq run.

New tools belong in `src/little/tools`, need a host registration and risk policy, and require meaningful boundary tests when they touch privileged resources. React components request structured host actions; they never call filesystem/process APIs or create grants.

## Git, memory, MCP and review workers

SAFE `git_status` and `git_diff` use the exact workspace Git root, current protected regular-file inventory, fixed literal arguments, bounded owned processes, redacted output, and disabled hooks/external diff/textconv/filter/fsmonitor/pager paths. They never stage or commit. Deleted paths and unavailable historical originals are omitted because fresh policy cannot authorize them. **Review Git changes** opens staged/worktree patches in native read-only documents. **Saved checkpoints** opens validated recorded or interrupted transactions for native confirmed recovery.

SAFE `get_project_memory` retrieves bounded user notes with evidence labels; source-backed entries are rechecked against current source policy. Every connected MCP tool has EXECUTION risk and an opaque namespaced tool identifier. The native host shows exact arguments and server endpoint for a fresh **Allow once** confirmation; ASK/PLAN/EDIT cannot invoke it. See [memory and integrations](integrations-memory.md) for transport/schema limits and side-effect boundaries.

AGENT can call SAFE `delegate_reviews` once per run. It starts two independent read-only ASK runtimes for architecture and verification, using the selected provider/model, private copied contexts, and local file-reading tools only. Each worker is limited to four iterations, 12,000 reported usage tokens and 4,000 result characters. Groq workers run sequentially with a 180-second deadline each so observed allowance can pace the second; other providers run in parallel with 60-second deadlines. These are additional model sessions with separate budgets. Workers have no Git subprocess tools, writers, project commands, MCP or recursive delegation. Their visible queued/running/terminal statuses reflect actual scheduling and results; a finished verification review does not mean tests ran. **Compare reviews** prepares the request for the composer so the user can review and send it.

## Approved local browser inspection

AGENT exposes EXECUTION `inspect_local_app` after source inspection and a visible plan. Every invocation needs native approval for the exact local URL and configured debug endpoint. The client creates its own temporary tab, blocks document navigation outside the approved origin, captures bounded rendered text and an optional PNG, and closes only that tab. Text can enter provider context; screenshots stay in native preview. Human **Inspect local app** uses the same consent and client, with native text/image editors. This foundation does not click controls, choose existing tabs, or execute model-supplied JavaScript. See [browser preview](browser-preview.md) for setup, limits, and real Chromium/native evidence.
