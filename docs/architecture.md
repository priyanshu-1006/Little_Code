# Architecture

Little Code is a standalone Electron/Code-OSS application with a bundled internal extension. The native workbench retains the editor, Explorer, search, terminal, and Git integration; Little Home and the right Agent panel are isolated webviews. The pinned Windows package and independent first launch have been verified. An installed VS Code development host remains an optional adapter-debugging workflow.

```text
Native Little Code workbench
  -> bundled extension host adapter <-> isolated React Agent / Little Home
      -> AgentRuntime <-> provider-neutral LLMProvider -> Groq / Ollama
      -> read-only WorkspaceService
      -> format readers / metadata -> notebook cells, DOCX/PPTX/PDF text, file hashes
      -> file request evidence/routing -> required schemas / bounded correction
      -> RepositoryHost -> incremental RepositoryIndex -> query ranking / fresh source context
      -> EditReviewHost -> staged edits / checkpoints / native diff
      -> CommandReviewHost -> one-use approval -> ProjectCommandService
      -> ProjectFeaturesHost -> private project memory / explicitly connected local MCP
      -> GitReviewHost / GitService -> bounded protected status and read-only patches
      -> once-per-run review team -> two isolated read-only AgentRuntime workers
```

[src/little](../src/little) owns the provider-neutral runtime, context, policies, structured tools, and React UI without editor API dependencies. [src/extension](../src/extension) adapts editor snapshots, diagnostics, workspace trust, SecretStorage, native dialogs/diffs, output channels, and webview messages. [Guarded native patches](../desktop/patches/little-workbench.mjs) verify the upstream pin and exact source anchors before integrating branding, onboarding, account-provider guards, and default right-sidebar placement. See [development.md](development.md) for packaging and native build evidence.

The [UI protocol](../src/little/ui/protocol.ts) accepts strict action shapes. Credentials and permission grants remain in the host; renderers receive metadata, redacted results, and opaque decision IDs. Webviews use local bundles/fonts/assets, nonce-based scripts, restrictive CSP, and safe text rendering. Groq keys use native encrypted SecretStorage and are never passed through webview messages or prompt configuration.

[RepositoryHost](../src/extension/repository-host.ts) owns bounded in-memory project maps and native file watchers. [RepositoryIndex](../src/little/context/repository-index.ts) refreshes protected inventory, reuses unchanged metadata, and commits only a complete stable scan. Query ranking selects fresh protected source snippets with line citations and visible reasons inside the shared context budget. Background scans wait while a run owns the index; metadata tools remain read-only and cannot replace the runtime's required source-inspection action. See [repository-context.md](repository-context.md) for heuristic and persistence boundaries.

[AgentRuntime](../src/little/agent/runtime.ts) streams provider events and executes tools sequentially behind [mode permissions](../src/little/permissions/permission-engine.ts). ASK/PLAN are read-only. EDIT stages reviewed file transactions. AGENT additionally requires relevant inspection evidence and a published visible plan before writes or commands. Existing-file edits need contents; create-only tasks may inspect the actual parent, and whole-file deletion may inspect exact-byte metadata. Each diff needs native review/acceptance and a pre-write checkpoint; each structured command needs explicit one-use approval plus native confirmation. Commands use current-user permissions, not an OS sandbox; project-code side effects can extend outside the working directory or use the network.

Version **0.2.0** routes explicit file requests through [bounded workflow rules](../src/little/agent/file-instructions.ts). Literal target paths are masked before intent checks while preserving the original path ledger, formats and workspace normalization. `slides.pptx` therefore does not supply a slide-operation noun, and `update.ts` does not supply a mutation verb: whole-file deletion can inspect metadata, while actual cell/slide edits and read-before-delete requests need contents. Available format-specific readers and writers are retained by the request budget. The runtime tracks relevant target evidence and observed proposal outcomes, withholds ungrounded file claims, and permits one corrective continuation after a valid answer skips required tools. Provider errors are not replayed, rejection cannot mint a later acceptance, and exact selected-workspace normalization prevents sibling paths from matching the target ledger. These prompt/prose rules are heuristic; protected tools and native host permissions remain the trust boundary.

`read_notebook` returns bounded cells/focused lines without outputs; `read_document` extracts DOCX paragraphs, PPTX slides and PDF pages; `inspect_file` exposes regular-file size/hash without contents. Dedicated reviewed adapters create/edit notebook cells, create simple documents, preserve DOCX/PPTX parts during text replacements, and append PDF text pages. Generic proposals handle UTF-8 edits/creation and whole-file deletion. Binary bytes and recovery originals stay in the host; model/UI observations receive bounded text/metadata rather than binary payloads. Legacy DOC/PPT, encrypted documents, OCR, arbitrary binary edits and in-place PDF text/layout replacement remain unsupported. See [file workflows](file-tools.md).

Groq uses native local function calls and SSE text; GPT OSS disables parallel calls. The same native request builder supplies transport and full-request budgeting, preserving canonical assistant/tool history and a bounded output reserve. Complete call validation precedes executable events. Host validators, source restrictions, mode permissions, reviews and approvals remain authoritative. See [provider design](providers.md).

[Events](../src/little/shared/contracts.ts) report run state, text, context, actions and observed verification. Saved project conversations persist separately in native workspace storage: display text and recent completed-turn context restore, executable bindings and approvals do not. See [conversation storage](conversations.md).

Checkpoints preserve exact original bytes, including binary and deleted files, and write-ahead mutation intents in private workspace storage. Interrupted apply and restore operations are discovered after restart; recovery protects later saves, deletions and policy changes as conflicts. Actual process-crash boundaries are tested, while Windows power-loss durability and external-write coordination remain limited. Command side effects are outside checkpoint coverage. [Checkpoint recovery](checkpoints.md), [file tools](file-tools.md), [tools.md](tools.md) and [agent-runtime.md](agent-runtime.md) specify the current boundaries.

Project memory persists user conventions, reviewed source-backed facts and labelled inferences with atomic writes in private project storage. Relevant notes and application-scoped preferences share the normal context budget and cannot grant permissions. MCP connects only user-configured loopback Streamable HTTP servers: discovery requires native consent, and every execution requires Agent inspection/plan plus a fresh native confirmation. Tool annotations do not lower risk, server side effects are outside checkpoints, and stdio/remote authentication are not implemented. Two isolated read-only review workers can inspect local source once per Agent run, with separate bounds and visible actual outcomes; they cannot write, run checks, invoke MCP, or delegate further. See [integrations and memory](integrations-memory.md) for scope and supported protocol versions. Approved local browser snapshots use a verified loopback Chromium endpoint and a fresh owned tab, with a document-origin gate and native screenshot preview; arbitrary scripts, interaction and existing-tab selection are unavailable. See [browser preview](browser-preview.md).
