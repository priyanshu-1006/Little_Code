# Project memory and integrations

Open the Settings gear in Little Agent. **Project memory** adds, edits and deletes notes through native dialogs. Choose a user convention, a user-reviewed fact, or a lower-confidence inference. Facts require a currently permitted, nonempty project source file; this checks provenance and access rather than proving the sentence's semantic truth. Sources newly ignored or missing are omitted from model context. Notes remain editable in private storage. Saving shows the redacted text and asks for explicit review. Relevant notes may be sent to the selected provider.

Memory is bound to the exact project identity, stored outside source files in Little's workspace storage, and survives app restart. Strict versioned records, directory identity checks, link rejection, fresh reads, cross-host serialization, fsync and atomic rename protect updates. Limits are 50 entries, 120-character titles, 4,000-character content, 128 KiB aggregate storage, and 3,000 characters of retrieved memory in the shared 20,000-character context budget. Corrupt stores are reported rather than silently overwritten. **Personal preferences** adds up to 1,500 characters of user-controlled conventions across projects. Memory and preferences cannot override mode permissions or authorize execution. Session conversation persistence remains unfinished.

**MCP integrations → Add MCP server** stores a name and an already-running loopback HTTP endpoint, such as `http://127.0.0.1:3000/mcp`. **Connect** requests native consent before protocol metadata and tool discovery; saved configurations never auto-connect on restart. This client supports current [2026-07-28 Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) with per-request protocol metadata, and legacy 2025-11-25, 2025-06-18 and 2025-03-26 initialize/session negotiation. A legacy fallback is restricted to an unrecognized HTTP 400 discovery probe. Recognized modern errors and failed tool executions are never downgraded or replayed.

The client supports bounded JSON/SSE tool discovery and text/structured results, cancellation, and a strict documented implementation subset of JSON Schema. Unsupported schema validators, media/resource content, sampling, elicitation and interactive result flows are rejected. There are at most eight configured servers, 50 discovered tools per server, and 16 remote tools exposed per run within 12,000 schema characters. HTTP requests reject redirects, credentials and remote endpoint hosts. No stdio process launch, remote OAuth, background server startup, or general third-party integration catalog is included.

Every remote tool has execution risk regardless of its annotations. ASK, PLAN and EDIT cannot invoke it. AGENT must first inspect source and publish a visible plan; then a native **Allow once** dialog shows the server and exact bounded, redacted arguments. Rejection/cancellation causes no call. Configuration, trust, current project and connection identity are checked again before execution. The server runs with its own permissions; it can read files, change external state or access the network. Its effects are outside file checkpoints, and closing a request cannot guarantee external work is undone. Results become untrusted context for the selected provider.

Real loopback HTTP fixtures cover both protocol eras, tool schemas, SSE framing, privacy, redirects, errors and cancellation. A separate packaged-app smoke uses genuine Settings controls and native dialogs for provider discovery/chat, note review/save, MCP discovery/disconnect and restart persistence; it uses local test servers, not a real Ollama engine or a live Groq key. See `desktop/screenshots/features.json` for its recorded outcome when present.
